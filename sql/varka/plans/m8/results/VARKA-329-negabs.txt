they became one lanewise NEG or ABS.
Run on the laptop: AMD Ryzen AI 9 HX PRO 370 (Zen 5, AVX-512 on 256-bit units), OpenJDK
25.0.4.1+1-1-26.04.4-Ubuntu, Linux 7.0.0-38-generic, power profile performance. First on 23 October 2026 (20:31
to 20:45 CEST), one run per tree and width at 512 and 256 bits; then on 24 October (00:13 to 00:38 CEST), three
runs per tree and width at 512, 256 and 128 bits, which the tables below report.

== code ==
Before: `varka-review-fixes-2` at de8cc490d35 with the benchmark's two new shapes added, built as that tree's
compiler builds them: -y1 a multiply by -1, abs(y1) IfElse(y1 < 0, -y1, y1) over a literal 0.
After: `varka-review-fixes-3`, the tree of the commit that adds this file (its last edits touched comments, tests and
skip lines, no emission): -y1 a lanewise NEG, abs(y1) the negation node with its abs flag,
a lanewise ABS. Class: sql/catalyst/src/test/java/org/apache/spark/sql/VarkaNarrowEmitBenchmark.java.

== command ==
As results/VARKA-329-emit-arm.txt: one JVM per run with the Test javaOptions and classpath of each tree,
  taskset -c 0,12,13,14,15,1,2,3 flock heavy.lock flock heavy2.lock \
    java -Xmx4g <Test javaOptions> --add-modules=jdk.incubator.vector -XX:MaxVectorSize=<64|32|16> \
      -XX:CompileCommand=quiet "-XX:CompileCommand=dontinline,org.apache.spark.sql.varka.bench.NarrowEmit*::loop*" \

both arms in one JVM (the default), no other JVM running and the load under 1.5 at each start. The 24 October
runs go repetition by repetition, each width in turn and before then after within it, so a drift of the machine
falls on both trees. Every case settled after 8 drives with its loops at level 4. Shape e (the CASE store) is in
neither change and is the control: its medians read the same on both trees, within 5 %.

== reading ==
On the native arm, the default since row 478, a byte negation and abs run 3.0x to 3.5x faster in L1 at 512 and 256
bits and 3.4x to 3.7x at 128 bits, 2.1x to 2.3x at 512 KB (3.2x to 3.6x at 128 bits), and 1.15x to 1.26x at 2 MB,
where the store is memory bound (2.0x to 2.2x at 128 bits): the byte multiply x86 lacks is gone (NEG is a subtract
from zero) and abs is one ABS instead of a compare, a multiply and a blend. On the widened arm abs gains 1.42x to
1.46x at 512 and 256 bits and 1.19x to 1.20x at 128, and the negation 1.01x to 1.07x. No cell is slower. The three
runs of a cell agree within 4 % on shapes f and g, except one run 10 % low (g, native, 256 bits, 262144 rows),
against gains far larger; the 23 October single runs of f and g fall within 7 % of these medians.
